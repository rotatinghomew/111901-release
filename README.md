# 健身参与数据对外披露与多期简报分发

本项目围绕社区全民健身公共服务的本地分析资料。数据均为合成记录，文件字段与时间口径按各自数据文件表示。项目目录包含业务资料、分析软件包和基础数据检查。

## 环境与运行

需要 Python 3.11 或更新版本，无第三方运行依赖。进入项目目录后运行 `python -m unittest discover -s tests -v` 检查合成资料。分析包位于 `src/release`，可从 Python 导入。输入资料位于 `data/`，CSV 使用 UTF-8 编码和首行字段名，策略资料采用 JSON。

## 数据约定

所有居民、机构、地点与活动均为虚构标识，时间以数据字段的本地日期表示。空字段表示该资料没有登记值，不应据此推断业务事实；具体数据口径以相应字段和 JSON 政策文件为准。资料用于离线分析，不含外部服务或凭据。

## 发布流程（`src/release`）

面向街道与承办机构的简报准备、审核、定时发送和本地回执全部在本地完成，不调用任何邮件或网络服务。

| 模块 | 作用 |
| --- | --- |
| `policy.py` | 读取最小保护单元、保护区间宽度和允许的合并范围 |
| `model.py` | 台账、指标口径、已发布记录、送达回执与可见性判定 |
| `bounds.py` | 依据可见记录推算每个格的人数区间（含差集、并集与到场率） |
| `planner.py` | 判定可公开 / 仅可合并 / 内部保留 / 待核核实，并给出不含保护数值的解释 |
| `workflow.py` | 发布单、审批、定时发送、撤销、重发、本地回执与送达清单 |

### 判定原则

* **保护看区间，不只看数字。** 某组人数低于最小保护单元时，若已公开或本次拟公开的总数、其余组、重叠口径的差集能把它推断到保护宽度以内，就不得放行。先发总数再逐组补发因此会被拦下。
* **空值不是零。** 缺少分母的到场率不计算、不放行；相关格只能“待核核实”。
* **重叠名单不相加。** 没有名单证明互不重叠时，参与人数只给出区间或改用人次口径。
* **口径由单位、时段、名单和指标定义确定**，不由报表标题决定。
* **撤回不等于没看过。** 已发送、送达不明和已撤回的记录都计入可见范围；只有证明未送达才移出。
* **联合判定。** 定时发送按同一阅读者合并判定；一次实际发送后，其他已批准但尚未发出的发布单重新核对，必要时撤回，编辑可改审聚合范围。
* **内部报告是证据**，保留全部数值；对外材料从不写入保护数值。

### 命令行

```bash
python -m release --book book.pkl explain --period 2026-03 --alternatives
python -m release --book book.pkl prepare --period 2026-03 --recipient partner-a
python -m release --book book.pkl approve --material m1 --editor alice
python -m release --book book.pkl schedule --approval a1 --due 2026-04-05T09:00:00+08:00
python -m release --book book.pkl send --approval a1 --delivered yes
python -m release --book book.pkl manifest --out manifest.json
```

`send` 只写本地 `outbox/<receipt>.json`（回执 + 当时的内容哈希和发布单）。`manifest` 把审批、定时、实际发出与回执连起来，可核对合作方收到的是哪一版，而不只是生成了几个文件。
